## 1. Context

InternalBeyond 是**单用户、本地优先**的桌面应用：Tauri Host + 一组本地 Node 服务（bridge / Active / Home Node / static），共享同一用户数据目录 `%LOCALAPPDATA%\InternalBeyond`。凭据权威是**加密 Vault**（`credential-vault.json` + `credential-vault.key`），读取缝是 Node 模块 `active/credential-resolver.js`（Tauri `credential_resolve` 只是它的 IPC 封装）。

P34.2 证实：Desktop/MB 平面已收敛到 Vault；**Home Node 执行平面仍是明文**（`character_runtime_specs.spec_json.apiKey`，14/14 行），且被当前运行时读取（`execution.js`、`understanding-derivation.js`）。本 ADR 在实现前**冻结**关键决策。

## 3. Decision 1 — Home Node Credential Access Model

### 评估
| Option | 机制 | 权限边界 | 安全风险 | 延迟 | 离线能力 | 维护成本 |
| --- | --- | --- | --- | --- | --- | --- |
| **A 直接 resolver** | Home Node 进程内复用 `active/credential-resolver.js`（读本机 Vault） | Home Node 进程获得解 Vault 能力；用 allowlist 收窄到自身角色 | 中（同机同用户，进程可读 Vault 文件） | 本地解密，~ms | 本地可用（无网也能解析） | 低（复用现有模块） |
| **B Broker** | Home Node → Broker（新 IPC/端点）→ Vault | secret 不进 Home Node；Broker 持权 | 低（隔离最强） | +IPC 往返 | 依赖 Broker 存活 | 高（新进程/端点/生命周期/审计） |
| **C Local Credential Service** | Home Node → 独立本地凭据服务 → Vault | 同 B（独立进程） | 低 | +IPC 往返 | 依赖服务存活 | 高（新进程） |

### 冻结
```
DECISION:         Option A — Home Node 直接复用本地 Credential Resolver
                 （在 Home Node 内建立薄 access layer：`services/home-node/credential-access.js`
                  包装 active/credential-resolver.js；allowlist = 本 Node 的 character bindings；
                  请求作用域 lease，不缓存、不落库、不日志）
RATIONALE:
  · IB 是单用户本地应用；Vault authority 已经以 Node 模块形式暴露，Home Node 本就是同机同时段的本地 Node 服务；
  · 复用既有 resolver 契约（零新协议、零新进程），延迟=本地解密，离线可用（本地 Vault）；
  · 与 Tauri Host 架构一致：桌面经 Tauri IPC→CLI（子进程）读 Vault，Home Node 经同机模块读同一 Vault，属同一 authority 的两种同机入口；
  · 维护成本最低，且不引入第二个 secret store。
REJECTED OPTIONS:
  · Option B（Broker）：单用户本地场景下，Broker 引入新 IPC/端点/生命周期/审计面，收益（隔离）有限（同机同用户本就可读 Vault 文件），成本与攻击面不划算。
  · Option C（独立 Local Credential Service 进程）：与 A 能力等价却新增一个常驻进程/端口/启动顺序依赖，属重复 surface；若未来需要跨用户/多进程隔离再引入（保留为将来方向）。
```

**权限收窄（与 Decision 5 一致）**：allowlist 只含 Home Node 自身 `characters`/spec 的 binding；请求作用域 lease；失败即 fail-closed；不缓存、不写盘、不日志。

## 4. Decision 2 — credentialRef Identity Model

### 选项
- **Model A**：`credentialRef = character_id`（`{"credentialRef":"friend_xxx"}`）。
- **Model B**：独立身份 `cred_xxx`（角色→映射→credentialRef）。

### 证据
P34.2：Vault binding id == apiConfig id == `character_runtime_specs.character_id`，**14/14 快照值与当前 Vault 一一对应**。

### 冻结
```
DECISION:         Model A — credentialRef = character_id（P34.3 身份模型）
                 并把 credentialRef 视为**不透明绑定 id**（opaque），以便将来切换到 Model B 无需改写消费者。
RATIONALE:
  · 现有 14/14 已天然对齐，零额外映射、零数据迁移成本；
  · 复用现有 Vault binding（Web Core 凭据流已按 apiConfig id 绑定）；
  · opaque 约定保证“将来独立 cred_*”只是把 ref 指向另一绑定，而非重写读缝。
RULES:
  naming   : credentialRef 是不透明字符串（同 resolver bindingId 字符集 [A-Za-z0-9_.:-]，≤180）；
             当前取值 = character_id（= apiConfig id）。
  ownership: binding 由 **Web Core（apiConfigs）** 拥有；Home Node 只**引用**，绝不创建/轮换绑定。
  lifecycle: binding 的创建/轮换/删除由 Web Core 凭据流负责；Home Node 侧 spec 只保存 ref；
             ref 解析失败 = 该角色“无可用配置”（fail-closed），不自动补建。
REJECTED OPTIONS:
  · Model B（现在就引入独立 cred_*）：为当前单用户场景增加一层映射与迁移，收益（换 Key/多角色共享）
    当前并无需求证据；保留为将来扩展（由 opaque ref 兼容承接）。
```

## 5. Decision 3 — Offline / Failure Policy

约束：**禁止明文 fallback**。

### Failure Policy Matrix（冻结）
| 状态 | 行为 | 是否允许 |
| --- | --- | --- |
| Vault 可用 | 请求作用域解析 secret → 单次请求使用 → 丢弃 | YES |
| Vault 暂时不可用（key/data 不可读/结构损坏） | **fail closed**（该回合/该 tick 报 `credential-unavailable`/`no-config`） | YES |
| 网络不可用 | 凭据解析为**本地**操作，不受影响；provider 调用失败属另一层（provider-error） | YES（解析照常） |
| credential 不存在（无 binding） | **fail closed** → 角色无可用配置（`CONFLICT`） | YES |
| resolver timeout | **fail closed** + **有界重试**（同请求内，次数/时限小；不跨请求缓存） | YES |
| encrypted local cache（本地加密缓存 secret） | **拒绝**（会成为第二个 secret store，破坏单一 authority） | NO |
| memory-only lease（请求作用域） | **允许**（仅请求生命周期，不跨请求、不落盘） | YES |
| plaintext fallback（回退 spec.apiKey） | **禁止**（迁移终态） | NO |

```
DECISION:         fail-closed + request-scoped memory lease + bounded retry；禁止 plaintext fallback 与 encrypted local cache。
RATIONALE:
  · 凭据解析在本地，无需 off-line 持久缓存即可离线可用；
  · 任何“缓存/回退”都会重新引入第二个 secret 面，违反 §2 单一 authority 不变量。
```

## 6. Decision 4 — DTO Compatibility Strategy

（DTO 本身不含 spec，故 mobile 兼容不受影响；此处针对 **spec 形状** 的过渡兼容。）

```
DECISION:         4 阶段灰度（与 P34.3-A §7 一致）
  Phase 1  reader supports both : 读优先 resolve(credentialRef)，缺 ref 时回退 spec.apiKey
  Phase 2  writer emits ref only: mapSpec 不再写 apiKey，只写 credentialRef（可运行判据改看 ref）
  Phase 3  remove apiKey reader : 删除 spec.apiKey 读取/回退
  Phase 4  cleanup data         : 受控清理历史 spec.apiKey（需快照 + 授权）
RATIONALE:
  · 先让读者具备“解析 ref”的能力，再停写明文，避免出现“角色突然不可运行”；
  · 终态无明文、无回退。
ROLLBACK:         保留旧 spec.apiKey 直到 Phase 4 之后；任一阶段失败 → 还原代码 + 保留/回灌旧 spec。
MIXED-VERSION:    ⚠️ “新 writer + 旧 reader”在无回退时会使角色不可运行 →
                  发布/升级必须保证 Phase 1（双读）先于 Phase 2（只写 ref）灰度到位。
MOBILE COMPAT:    NO IMPACT —— spec 永不进入 DTO（`mobile-dto.js:131`、`device-registry.js:683-712`）。
```

## 8. Migration constraints（冻结的硬约束）

1. **单一 authority**：明文仅运行时内存；持久层仅加密 Vault。不引入第二个 secret store。
2. **无 schema 变更**：`spec_json` 为 JSON blob → `apiKey`↔`credentialRef` 仅字段级变化，无 DDL。
3. **DTO 不出站 / Recovery DEFER / economy 边界** 保持不变。
4. **灰度顺序**：Decision-4 Phase 1 先于 Phase 2；禁止“只写 ref 的 writer”在没有双读 reader 时上线。
5. **fail-closed**：任何解析失败不得回退明文、不得静默降级。
6. **不清历史数据**：Phase 4 需单独授权 + `home-node.db` 快照 + controlled test。
7. **不碰**：resolver 文件契约、Vault 加密/schema、Rust `credential_*`、Installer、Recovery、Active。

## 9. Rejected alternatives（汇总）

- **Option B / C（Broker / 独立 Local Credential Service 进程）**：单用户本地场景下成本/攻击面高于收益（Decision 1）。
- **Model B（独立 `cred_*` 身份，现在引入）**：无需求证据的额外映射；保留为 opaque-ref 兼容的将来项（Decision 2）。
- **encrypted local cache / plaintext fallback**：违反单一 authority 不变量（Decision 3）。
- **把 apiConfigs authority 整体搬到 Home Node（Strategy B）**：超出本阶段，且立即引出“谁能编辑角色”的更大问题（`home-node-bootstrap.js:571`）。

## 10. Future implementation boundary（P34.3-B 的边界）

**允许（P34.3-B，需单独授权）：**
- `assets/js/mobile-dto.js mapSpec`：去 apiKey、写 credentialRef、可运行判据改看 ref；
- `services/home-node/`：新增 `credential-access.js`（Decision-1 access layer）+ 在 `execution.js` / `understanding-derivation.js` 改为经 access layer 取 secret；
- `device-registry.js`：`getCharacterSpec` 附近提供解析入口（不返回 secret 到 DTO）；
- allowlist：Home Node 侧最小权限集合（仅自身 character bindings）。

**不允许（P34.3-B 也不做）：**
- 改 Vault schema/加密/Rust 契约；改 recovery/DEFER；改 economy 边界；改 Installer；任何明文 fallback；任何自动创建/轮换 Vault binding；在**生产**数据上做验证。
