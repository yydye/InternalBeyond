# P24-M3.5 · Explicit Targeting Contract（Structured Target Identity）

状态：**M3.5.1A 已实现**（structured target identity foundation）。Phase 0 审计 + 契约冻结见本文件；
后续 M3.5.1B（legacy 全量硬化）/ M3.5.1C（mention picker）尚未实现。

本阶段**不改**：`planParticipation`（仍 v3）、`plannerId`（仍 `group-rule-v1`）、reason 词表、
`group.participationPolicy`（仍只有 `maxResponders` / `recentSpeakerWindow`）、P23 五核心、Middle Brain、Memory、单聊。

---

## 1. Identity domain

- canonical target identity = **`apiConfigs.id`**，与成员消息的 `metadata.speakerId` **同一 domain**；
- `groups.members[].characterId` 是同一个值（`getGroupMemberIds` → `apiConfigs.find(a=>a.id===mid)`），不是第二套身份；
- display name（`nickname` / `model`）只是文本 token 与展示层，**永远不是** targeting identity。

## 2. Canonical field

```js
// 群用户消息（role:'user'）
{
  id, role:'user', content:'@流萤 今天怎么样？', friendId:'group_…', timestamp,
  metadata: { targetSpeakerIds: ['friend_liuying'] }   // 始终写入；无 target ⇒ []
}
```

- **新群用户消息总是写该字段**（即使没有 target ⇒ `[]`）；
- `presence` = 该消息经过 structured targeting writer；`missing` = legacy 消息；
- 本阶段**不**写 `metadata.groupTurnId`：它可由 `userMsg.id` 纯派生（`groupTurnIdFor`），落库等于制造第二份可推导事实；
  `turnId` 属于 P23，**绝不**写到用户行。

## 3. 纯契约（`assets/js/group-runtime-core.js`）

| API | 语义 |
|---|---|
| `TARGETING_ERRORS` | `['bad-target-list','bad-target-id','duplicate-target-id']`（闭集） |
| `validateTargetSpeakerIds(ids)` | **结构校验**：必须是 array；每项必须是非空 string、无首尾空白、无控制字符、非凭据形态；不允许重复。返回 `{ok,errors}`，**不涉及**"是否属于当前群" |
| `canonicalizeTargetSpeakerIds(parsedIds, participantIds)` | 文本/任意顺序 → **participant 顺序** + 去重 + 只保留当前参与者（历史退出者不报错、也不进入结果） |
| `resolveTargetSpeakerIds({message,text,candidates,participantIds})` | **结构化优先**读取器：own `metadata.targetSpeakerIds` 存在 ⇒ 唯一权威（空数组也权威）；缺失 ⇒ legacy 文本解析。非法 structured ⇒ 抛 `TARGETING_CONTRACT` |
| `projectTargetedParticipants(targetSpeakerIds, participants)` | ids → 当前参与者中被点名的 id（participant 顺序），供 adapter 生成 `mentioned` 布尔 |

纯度：零存储 / 零 DOM / 零网络 / 零时钟 / 零随机（与 core 既有约束一致）。

## 4. Reader precedence（migration contract 的核心）

| 消息状态 | 行为 |
|---|---|
| `metadata` 有 own `targetSpeakerIds`（含 `[]`） | **结构化权威**；**绝不**重新解析 content |
| `metadata` 没有该字段 | legacy：`resolveMentionTargets(text,candidates)` → canonicalize |
| 字段存在但非法（非数组 / 非法元素 / 重复） | **fail closed**（`TARGETING_CONTRACT`）；**绝不**回退文本解析 |
| 字段含非当前成员的 id（历史事实） | 不报错；projection 只映射当前参与者 |

**structured empty 语义**：`content='@B'` + `metadata.targetSpeakerIds:[]` ⇒ 结果 `[]`（不是 B）。

## 5. 写入纪律（one-write）

群分支顺序（`communication.js`）：

```
userMsg.id → groupTurnId 派生 → mention candidates → resolveMentionTargets
  → canonicalizeTargetSpeakerIds（participant 顺序 + 去重 + 仅当前参与者）
  → validateTargetSpeakerIds（writer invariant；非法 ⇒ fail closed，**不落库**）
  → userMsg.metadata = {targetSpeakerIds}
  → 单次 dbPut('chatMessages',userMsg)
  → canonical snapshot（一次）
  → policy resolver（一次）→ recent 派生（一次）
  → resolveTargetSpeakerIds（一次）+ projectTargetedParticipants（一次）
  → planner
```

- 每 GroupTurn：解析 **1** 次、结构化读取 **1** 次、投影 **1** 次、用户消息 canonical write **恰好 1** 次；
- 禁止 `persist → patch metadata → persist again`（会在 Home Node 产生假 revision）；
- legacy 消息**不回填**、**不重写 content**。

## 6. 语义：target ≠ exclusive

- `target` 只是 **priority / relevance signal**：unlimited 时所有人仍可回复；
- 不突破 `maxResponders`（`cap=1` ⇒ 被点名者；`cap=2` ⇒ 被点名者 + participant 顺序的下一个 eligible；`cap=0` ⇒ 空计划）；
- 被点名者属 tier1，**豁免 recent penalty**；`muted + targeted` 仍允许发言（与既有 `muted + mentioned` 完全一致）；
- `removed` = **hard deny**：历史 targeting 事实保留，但不复活已退出成员；
- 数组顺序**无语义**：canonical 写入按 participant 顺序，planner 仍用 participant 输入顺序（文本 `@` 顺序不会偷偷影响规划）。

## 7. 边界

| 边界 | 状态 |
|---|---|
| planner | `planParticipation` 零修改；只吃 `participants[].mentioned` 布尔；planVersion 仍 3 |
| policy | `group.participationPolicy` 仍只有两个字段；无 `targetOnly` / `mentionOverride` / `exclusiveTargeting` |
| P23 | 五核心对 targeting **零感知**（不进入 delivery planner / multimodal policy / sequence / runtime / voice core） |
| prompt | target ids **不**序列化进 provider prompt（只通过 mentioned 影响参与） |
| assistant metadata | **不**复制 targetSpeakerIds（只有 M1 的 groupTurnId / speakerId / groupOrder） |
| Memory / Middle Brain | 零修改、零 targeting 权威（未来 MB 可**只读**"是否被 targeted"，但不得改事实） |
| 单聊 | 单聊用户消息**不**写该字段 |
| cancel | 只停止未来 MemberTurn；已落库的 targeting 事实保留 |
| retry | 同一 GroupTurn 不重新解析（当前 group 成员调用无 retry，静态成立） |

# M3.5.1B · Historical Compatibility（历史 / replay / rename / membership / corruption）

状态：**hardening 完成**。生产语义未变（`planVersion` 仍 3、planner/policy/P23/MB/Memory 零改动、`DB_VER` 仍 24）。

## A. 真实历史消费者（审计结论）

| 类别 | 现状 |
|---|---|
| A. 只显示历史 | ✅ 存在：`loadChatMessages` / `_renderAllChat`（渲染 `content`；群消息只用 `metadata.config_id` 做发送者标记，**不读** `targetSpeakerIds`） |
| B. 作为 provider context 重新消费 | ✅ 存在但**只传 content**：群分支把快照映射成 `{role:'user',content:'[User] '+content}`，metadata 不进入 prompt |
| C. 重新执行 participation planning | ❌ **不存在**：只有本轮触发消息进入 `planParticipation` |
| D. 真正的 GroupTurn replay | ❌ **不存在**（`planParticipation(_gPlanInput)` 与 `resolveTargetSpeakerIds(` 各只有 1 个调用点，均在群发送分支内） |

> **historical targeting is persisted/readable, but participation replay currently has no production consumer.**
> **future replay MUST use persisted structured ids**（不得重新解析 content）—— 这条是给未来 replay / P25 编排的硬不变量。

## B. 历史读取语义（冻结）

- **structured 事实原样保留**：`resolveTargetSpeakerIds` 在 structured 路径返回**校验通过的持久化 ids**（含已退出成员的历史 id）——
  这是"用户当时 @ 了谁"的事实；成员映射交给 `projectTargetedParticipants`（只投影当前 participants）；
- **legacy 路径**（字段缺失）仍走文本解析 → canonicalize 到当前 participants（文本解析本就只认当前显示名）；
- **metadata container**：`metadata` 缺失 / `null` / 非 object（primitive/array）⇒ legacy（**不**炸掉历史）；
  只有 `metadata` 是 object 且 **own** `targetSpeakerIds` 存在时才进入 structured 校验；
- **corruption ⇒ fail closed**（`TARGETING_CONTRACT`，闭集 `bad-target-list` / `bad-target-id` / `duplicate-target-id`），
  绝不回退文本解析；错误信息**不回显**原始 id 或凭据形态值。

## C. rename / membership / rejoin

| 情形 | 行为 |
|---|---|
| structured-era 改名 | 历史 `targetSpeakerIds` **不变**（id 稳定）；读取**不重解析** ⇒ 不会漂移 |
| structured-era 改名碰撞（B→萤、C→流萤） | 历史仍指向 **B**，绝不改判给 C（structured persistence 的核心价值） |
| legacy-era 改名 | **best-effort**：文本解析可能 unresolved 或命中改名后的新角色 —— 这是 legacy 的**已知限制**，不猜、不回填 |
| legacy-era 同名 | ambiguous ⇒ `[]`（绝不任选） |
| legacy-era 未知 | `[]`（不 fail 整轮） |
| 成员退出 | 历史 fact 保留该 id；projection 只映射当前参与者；仍在 participant list 且 `status='removed'` ⇒ planner **hard deny** |
| 成员重新加入 | 支持（`addGroupMember` 恢复 `removed → active`）；历史 fact 仍指向**同一 id**；**不**自动 replay 历史 GroupTurn |

## D. 不可变性 / 显示边界 / roundtrip

- **历史读取、rename、成员变更、legacy 回退、corrupt 读取：全部 0 次 chatMessages 写**（运行期计数探针 + 行指纹比对）；
  **不自动修复** corrupt 行、**不回填** legacy 行、**不重写** 历史 content；
- **display ≠ planning**：历史行 metadata 损坏时，聊天 UI 仍正常显示 `content`（不弹"本轮参与计划不可用"）；
  只有真正消费该行的 planning consumer 才 fail closed；
- **provider history**：历史 user 行的 `targetSpeakerIds` 不进入 prompt；
- **roundtrip**：IndexedDB 与 export→import **都保留三种状态的区分** —— `[ids]` / `[]` / **missing 仍是 missing**（绝不把 missing 变成 `[]`）。

## E. 删除 / 复制

- 删除消息或删除群：targeting 随 message 行一起消失（`dbDelete('chatMessages', …)`），**没有**独立的 targeting cleanup job（无第二 store）；
- 群/消息 clone 或 duplicate：**本仓库不存在该功能** ⇒ N/A（未新增）。
