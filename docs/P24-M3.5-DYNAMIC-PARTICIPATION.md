# P24-M3.5.2 · Dynamic Participation（Runtime 决策权威 + Foundation）

状态：**M3.5.2A foundation 已实现**（runtime-only 准入队列 + hard gates + 记账）。
**未实现**：SILENT / DEFER / INTERJECT / Group Brain / 任何模型驱动的动态决策。
`planVersion` 仍 3、`plannerId` 仍 `group-rule-v1`、`group.participationPolicy` 仍只有两个字段、
P23 五核心零改动、`DB_VER` 仍 24、无新 store。

---

## 1. 权威划分（Phase 0 冻结）

```
Participation Planner (v3，零修改) = GroupTurn start-time static admission authority
├─ initial SPEAK  → entries[]（order = planned order）
└─ initial OMIT   → omitted[]（removed / muted-not-mentioned / budget-limit）

Group Runtime（本文件）            = dynamic execution authority
├─ 执行初始计划（串行 + cancel checkpoint）
├─ runtime SILENT（**未实现**；未来语义 = terminal no-message）
├─ DEFER v1（**未实现**；未来语义 = 把既有 pending MemberTurn 移到队尾，同一 order/turnId）
└─ INTERJECT（**deferred/blocked**，见 §5）

Group Brain  = 未来 recommender only（当前不存在）
Character MB = 未来 recommender only（本阶段零修改）
P23          = 只交付"已被 admitted 的 MemberTurn"（零动态感知）
```

## 2. Foundation 契约（`assets/js/group-runtime-core.js`）

| API | 语义 |
|---|---|
| `DYNAMIC_RUNTIME_ERRORS` | 闭集：`bad-group-turn-id` / `bad-entries` / `bad-speaker-id` / `bad-order` / `duplicate-speaker` / `duplicate-order` / `bad-cap`（不回显原始 id） |
| `DYNAMIC_GATE_REASONS` | 闭集：`queue-empty` / `cancelled` / `unknown-entry` / `already-started` / `removed` / `cap-reached` |
| `validateDynamicRuntimeInput(input)` | 校验 `groupTurnId` + `entries`（speaker 唯一、order 唯一且非负整数）+ `responderCap`；**不**校验 targeting / recent / policy / prompt |
| `createDynamicRuntimeState(input)` | 非法 planner output ⇒ 抛 `DYNAMIC_RUNTIME_CONTRACT`（fail closed，绝不静默修数据）；state = 初始队列（**planner 顺序原样**）+ started/completed/failed + statusSnapshot + cap |
| `nextDynamicRuntimeEntry(state, ctx)` | peek → hard gates → 通过才出队；deny 时不消费并返回 `{done:true, reason}` |
| `markDynamicRuntimeStarted / Completed / Failed` | 记账（failed 也算 started，**不重排、不 retry**） |
| `markDynamicRuntimeCancelled(state, reason)` | **telemetry only** —— cancel 的唯一 authority 仍是 `_gTurn.cancelled`（由 ctx 传入） |
| `dynamicRuntimeSnapshot(state)` | 只读快照（测试 / telemetry） |

## 3. Hard gates（execution-time invariant）

| gate | 规则 |
|---|---|
| cancelled | 最高优先级：`ctx.cancelled === true` ⇒ 拒绝且不消费队列 |
| unknown-entry | entry 必须属于 initial plan（speakerId + order 精确匹配） |
| already-started | **one MemberTurn per speaker per GroupTurn**（同一 speaker 不可二次准入/重试） |
| removed | `status === 'removed'` ⇒ deny（防 plan 之后状态被改） |
| cap | `responderCap !== undefined` 时 `started unique < cap` 才可启动；缺省 = unlimited（**绝不**把 null 当 0） |
| muted | **不是** runtime deny：muted + 用户点名由 planner 合法准入，runtime 不否决 |

## 4. 语义边界

- `groupOrder` 仍是**计划顺序**（planner 的 `entry.order`），runtime 不重编号、不排序、不压缩空洞（`0,2` 合法）；
- `turnId` 仍由 `memberTurnIdFor(groupTurnId, speakerId, order)` 派生 ⇒ 本阶段不新增 `runtimeOrder` / `admissionIndex`；
- targeting（`metadata.targetSpeakerIds`）与 recent（pre-turn 快照）**不进入** runtime state，也不被 runtime 修改；
- canonical metadata **不新增**动态字段；user metadata 不变；
- runtime state **不落库**（ephemeral；刷新/崩溃后 GroupTurn 不 resume）；无新 store、无 localStorage/sessionStorage 队列。

## 5. INTERJECT 为何 deferred（Phase 0 结论，本阶段未实现）

1. **无可实施人群**：planner 的 omitted 只有 `removed` / `muted-not-mentioned` / `budget-limit`，而所有 eligible 参与者都会被选中 ⇒ "eligible 但未被准入"的集合为空；
2. **身份/序号缺口**：omitted 者没有 planner `order`，而 `memberTurnIdFor` 只接受 `(groupTurnId, speakerId, groupOrder)` ⇒ 需要显式的身份契约扩展；
3. `removed` 永远 deny；`budget-limit`（cap 造成）不得突破；`muted` 未点名不得绕过 ⇒ 三条都排除了现有的省略池。

## 6. Feature gate 与等价性

- 开关：模块级常量 `IB_DYNAMIC_PARTICIPATION_DEFAULT=false`；测试可通过 `window.IB_DYNAMIC_PARTICIPATION` 覆写；
- **disabled**（生产默认）：不建 runtime state，循环逐字沿用既有 static 语义 ⇒ 0 额外模型调用 / 0 额外 DB 读 / 0 额外 DB 写 / 0 额外 canonical 消息 / 0 额外 metadata；
- **enabled（foundation，无 dynamic decision）**：同一份 entries 经 queue 驱动**同一个**循环体 ⇒ 与 static 在 provider 顺序与次数、canonical 行（speakerId/order/content/turnId 派生）、DB 读写计数、metadata 键集合上**全等**（差分基线测试）。

## 7. 未来阶段 seam

| 阶段 | 内容 | 前置 |
|---|---|---|
| M3.5.2B | Runtime SILENT（rule-first；模型建议 ≤1 次/GroupTurn；无 canonical 消息、只 trace） | A |
| M3.5.2C | DEFER v1（pending 重排；order/turnId 不变） | A |
| M3.5.2D | INTERJECT | **需先决策**：省略池来源（planner v4？）+ 身份/序号扩展 |
| M3.5.3 | Group Brain（recommendation-only） | A/B/C |

**不变量（写入契约）**：future dynamic decisions MUST NOT re-run the planner、MUST NOT 重解析 targeting / 重新 derive recent、MUST NOT 绕过 cap / removed / muted / cancel。

# M3.5.2B · Runtime SILENT

状态：**已实现**（runtime-only，默认关闭）。仍然没有 DEFER / INTERJECT / Group Brain / 任何模型调用。

## A. 决策词汇与契约

```js
DYNAMIC_RUNTIME_DECISIONS = { SPEAK: 'speak', SILENT: 'silent' }   // 闭集，仅两个
DYNAMIC_DECISION_SOURCES  = ['default', 'injected', 'fallback']     // runtime-only 诊断
DYNAMIC_DECISION_DIAGNOSTICS = ['decider-threw','malformed-result','unknown-decision','unsupported-decision']
```

- `resolveDynamicRuntimeDecision(state, entry, ctx)` → `{decision, source, diagnostic}`；
- **SILENT** = 一个**已经被 planner admitted** 的 MemberTurn 在 execution-time 终止自己：
  **不**产生 provider 调用 / typing / canonical assistant 消息 / roundExtras / P23 delivery；
  initial planner 的 admitted fact 保留（`plannedCount` 不变、`groupOrder` 空洞保留、targeting 事实不变）；
- SILENT **不是**：planner omission / provider failure / cancel / DEFER / empty输出 / P23 模态 / "……" 假消息 / system event。

## B. 顺序（本阶段最关键的不变量）

```
nextDynamicRuntimeEntry（hard gates：cancel → unknown-entry → 已 started/silent → removed → cap）
  ↓
resolveDynamicRuntimeDecision（可选语义层；缺省 ⇒ SPEAK）
  ↓ SILENT ⇒ markDynamicRuntimeSilent + continue（队列继续，不消费任何执行资源）
  ↓ SPEAK
_gTurn.startedCount++ → markDynamicRuntimeStarted → member identity → typing → provider → dbPut → roundExtras → completed/failed
```

决定点位于 `communication.js` 的成员循环内、`startedCount++` **之前**（源码行序：决策 seam → `_gTurn.startedCount++` → typing 创建 → provider 调用）。

## C. 记账与终态

- `silentSpeakerIds`（runtime-only）：`pending → silent terminal`，**不**进 started / completed / failed，**不**算 failure；
- **one MemberTurn per speaker per GroupTurn** 扩展为 **terminal（completed / failed / silent）不可再次准入**：对 silent 者再次准入 ⇒ gate `already-silent`；
- `markDynamicRuntimeSilent` 幂等保护：重复标记 ⇒ `{ok:false,reason:'already-silent'}`；已 started 者 ⇒ `{ok:false,reason:'already-started'}`。

## D. 决策来源（runtime-only）

- **生产默认**：无 decider ⇒ 恒 `SPEAK`（逐字等同 2A foundation）；
- 测试注入：`window.IB_DYNAMIC_PARTICIPATION_DECIDER`（仅 harness 使用；非产品 API、不持久化、不进 prompt / canonical metadata）；仅当 feature gate 打开时才会被读取；
- decider 只收到**最小只读上下文**（groupTurnId / speakerId / groupOrder + started/completed/failed/silent 的**数组副本**），拿不到 DB / group / provider 配置 / Memory / 凭据；
- decider **不能改 runtime state**（副本隔离，已由 S18 断言）；
- **失败策略**：抛错 / `null` / malformed / 未知词（含 `defer` / `interject`）⇒ **fallback SPEAK** + 闭集 diagnostic；**不**升级为 GroupTurn 失败、**不**写 canonical error。

## E. 与 hard gates 的边界

hard gates **先于**语义决策：removed / cancelled / cap 被拒绝的 entry **不会进入** decision source（S19–S21 用"decider 调用次数 = 0"证明；`I50` 用真实回合证明 cancel 之后 silent 候选不再被询问）。SILENT 无权绕过任何 hard gate。

## F. SILENT 与其它语义

| 交互 | 行为 |
|---|---|
| `groupOrder` | 空洞保留（A#0、C#2；绝不把 C 改成 1） |
| `turnId` | 不受影响（C 仍由 `memberTurnIdFor(groupTurnId,C,2)` 派生；silent 者不产生任何 canonical 行） |
| `plannedCount` | 不变（3） |
| `startedCount` | **不含 silent**（A SPEAK/B SILENT/C SPEAK ⇒ 2） |
| cap | **不补位**：`maxResponders` 是 maximum，不是 fill target；SILENT 不会让 planner 外的角色获得名额 |
| targeting | 被点名的 speaker **可以** SILENT（target = priority，不是 forced speech）；`targetSpeakerIds` 事实不变 |
| muted | `muted + targeted` 由 planner 合法准入，runtime **不**因 muted 自动 silent，也**不**阻止 decision seam（hard gate 只有 removed） |
| removed | 永不进入 decision（hard gate 先拒绝） |
| cancel | cancel 之后不会有新的 decision / silent / provider；已记录 silent 保留 |
| provider 失败 | 记 failed（**不是** silent）；后续成员继续 |
| 空输出 | 沿用既有 provider/member 行为，**不**重分类成 SILENT（SILENT 只发生在 provider 调用之前） |
| 全 SILENT | GroupTurn 正常 `completed`（不是 cancelled / failed）；**不**生成任何额外聊天消息（与 planner 的 empty plan 不同：empty plan 会显示"本轮无人回应"，all-SILENT 不显示） |
| roundExtras | silent 者不 push；后续成员只看到真正成功的前序回复，provider context 无任何 silent 痕迹 |
| recent | 不把 silent 者加入 recent（他没实际发言）；下一回合的 recent 仍只来自 canonical assistant 消息 |

## G. 边界冻结

| 边界 | 状态 |
|---|---|
| feature gate | 仍 `IB_DYNAMIC_PARTICIPATION_DEFAULT=false`；disabled ⇒ 不创建 runtime、**不读** decider hook |
| 模型调用 | 本阶段新增 **0**（decision 是纯函数） |
| P23 | 五核心对 silent / decision 零引用；SILENT 完全不进交付 |
| Memory / Middle Brain / Group Brain | 零改动、零 authority |
| 持久化 | `silentSpeakerIds` 仅内存；无新 store / 无 metadata / 刷新不恢复 |
| planner / policy / targeting / recent | 全部零修改 |
| DEFER / INTERJECT | 仍未实现（DEFER 属 M3.5.2C；INTERJECT 仍 blocked） |

# M3.5.2C · Runtime DEFER v1

状态：**已实现**（runtime-only，默认关闭）。INTERJECT / Group Brain / 模型决策仍未实现。

## A. 定义与执行流

```
hard gates（cancel → unknown-entry → already-started → already-silent → removed → cap）
  ↓
decision（speak | silent | defer；缺省 ⇒ SPEAK）
  ↓ defer ⇒ 该 entry 追加到本轮队列**尾部**，等本轮后续机会（**不是 terminal**）
  ↓ speak ⇒ startedCount++ → markStarted → identity → typing → provider → canonical → completed
```

例：`A DEFER → B SPEAK → C SPEAK → A SPEAK`；队列变化 `[A,B,C] → [B,C,A]`。

## B. SILENT vs DEFER

| | SILENT | DEFER |
|---|---|---|
| 终态？ | **是**（terminal，本轮不再回来） | **否**（回到 pending 尾部，之后仍会执行一次） |
| 记账 | `silentSpeakerIds` | `deferredSpeakerIds` |
| 后续资格 | 不可再准入（gate `already-silent`） | 可再次被取出并 SPEAK（仍受 one-turn-per-speaker 约束） |
| provider/typing/canonical/roundExtras/P23 | 全部 0 | 全部 0（直到真正 SPEAK） |

## C. 收敛与限制（防死循环）

- **同一 speaker 每 GroupTurn 最多 defer 一次**：第二次 defer ⇒ core 端 fallback SPEAK（`diagnostic='defer-limit'`）；
- `deferDynamicRuntimeEntry` 失败（`unknown-entry` / `already-started` / `already-silent` / `already-deferred` / `not-in-queue`）⇒ adapter 继续按 SPEAK 执行 ⇒ **绝不死循环、绝不丢 entry**；
- DEFER **不能**：从 omitted pool 拉人、释放/补位 cap、重跑 planner、重新 derive recent、重解析 targeting、增加 `plannedCount`。

## D. 不变量

| 维度 | 行为 |
|---|---|
| `groupOrder` | 不变（A#0 即使最后执行仍是 #0；绝不重编号） |
| `turnId` | 不变（最终执行时仍用原 groupTurnId + speakerId + order ⇒ 同一个 memberTurnId） |
| `plannedCount` | 不变（planner 仍 admitted A/B/C） |
| `startedCount` | defer 过程不计；只有真正 SPEAK 才计 |
| cap | 不补位（cap 是 maximum，不是 fill target） |
| targeting | 被点名者可 defer，targeting 事实不变 |
| muted | `muted + targeted` 可 defer；runtime 不自动 defer |
| removed | 永不进入 decision（hard gate 先拒绝） |
| cancel | defer 之后 cancel ⇒ 队列停止（deferred 不再恢复、不进入 decision） |
| provider / typing / canonical / roundExtras / P23 / recent | defer 过程全部为 0；真正 SPEAK 时恢复常规行为 |
| 持久化 | `deferredSpeakerIds` 仅内存；无 DB / localStorage / canonical metadata |
| INTERJECT / resumeEntry | 仍不存在（仅保留在后续阶段） |

# M3.5.2D · INTERJECT Contract Design（**设计冻结，未实现**）

状态：**contract only**。本阶段**没有**任何 production 行为：`interjectEntry()` / `resumeEntry()` /
`admissionPool()` 均不存在；`DYNAMIC_RUNTIME_DECISIONS` 仍只有 `speak / silent / defer`；
planner v3、policy 两字段、targeting、recent、P23、Memory、Middle Brain、Group Brain 全部零修改。

## A. Definition

> **INTERJECT** = 一个**原本没有进入 initial `plannedEntries`** 的 speaker，在当前 GroupTurn 生命周期内
> 获得**一次合法的 runtime admission**（= 一次 MemberTurn）。

它**不是** SPEAK（SPEAK 是执行既有 admitted entry）、**不是** SILENT（终态放弃）、**不是** DEFER
（已 admitted entry 的重排）。它是**第二层准入**：planner v3 仍只负责 initial admission。

## B. Non-goals（本阶段明确不做）

- 不实现任何 runtime 入口（`interjectEntry` / `resumeEntry` / `admissionPool`）；
- 不扩展 decision 词表（`'interject'` 只出现在本文档，不在 `DYNAMIC_RUNTIME_DECISIONS`）；
- 不引入新 participant identity、不改 planner / policy / targeting / recent / P23 / Memory / MB / Group Brain；
- 不新增模型调用、provider 调用、DB 结构或持久化。

## C. Candidate sources（**只记录，不选择**）

| 候选 | 说明 | 现状审计 |
|---|---|---|
| A. planner `omitted` entries | 唯一"由 planner 产生的、未获准入"的集合 | 现有 reason 只有 `removed`（永不允许）/ `muted-not-mentioned`（不得绕过）/ `budget-limit`（由 cap 造成，不得突破） ⇒ **当前无合法人群** |
| B. group members 全量 | 直接从群成员表取人 | 会让 runtime 重新判定资格 ⇒ 形成第二套 participation authority（与 planner v3 冻结冲突） |
| C. recent speakers | 以"最近说过话的人"为候选 | recent 是**上下文输入**（pre-turn 快照），不是资格/准入来源 |
| D. targeting candidates | 以用户 `targetSpeakerIds` 为候选 | 用户 targeting 是**事实**（M3.5.1 冻结）；把它当作准入池等于让 runtime 改写用户意图，且被点名者多数已 admitted |
| E. Memory recommendation | 以 Memory 推断候选 | Memory 不是 participation authority（M3.4 Phase 0 冻结） |

**结论（本阶段冻结的"事实描述"）**：在上述候选里，只有 (A) 属于 planner 权威内的集合，而它当前**没有可用人群**；
(B)(C)(D)(E) 都会引入第二套 authority 或改写用户事实。⇒ INTERJECT 的**候选来源必须先做契约决策**，本阶段不做选择。

## D. Authority boundary（冻结）

未来 INTERJECT **必须**经过既有 hard gates，**不得绕过**：
`cancelled`（最高优先级）、`removed`、identity 校验、`cap`、以及"同一 speaker 每 GroupTurn 最多一次 MemberTurn"。
INTERJECT **不能**：偷偷修改 planner output、产生第二套 cancel authority、在 runtime 里重判 eligibility。

## E. Identity contract（冻结）

- INTERJECT speaker **必须**拥有 **canonical memberId**（= `apiConfigs.id`，与 `metadata.speakerId` 同一 domain）；
- **不得**使用 displayName / 临时名字 / 昵称作为身份；
- **不得**创建新的 participant（不得出现不在群成员表里的 speaker）。

## F. Queue contract（待实现）

未来的 queue mutation 需要显式 API（三选一或组合，**当前未实现**）：`append tail` / `insert current` /
`priority insert`。任何 mutation 都必须保持"queue 只包含 canonical memberId 的 entry"且不改变既有 entry 的 `order`。

## G. groupOrder contract（**未冻结，需先决策**）

若 `A#0 / B#1` 已计划，C 通过 INTERJECT 加入，则 C 的 `order` 需要新规则。候选：
① 接在"最大计划 order 之后"；② 独立的 runtime ordinal（不改 `groupOrder` 语义）；
③ 把 `groupOrder` 扩展为"actual admission order"（**会破坏现有语义，明确不推荐**）。
**现有 `groupOrder` 语义（planned order，空洞合法、绝不重编号）不得修改**；在该规则冻结之前**不得实现 INTERJECT**。

## H. turnId contract（**未冻结，需先决策**）

- INTERJECT speaker 必须拥有 `memberTurnId`；
- 现状：`memberTurnIdFor(groupTurnId, speakerId, groupOrder)` ⇒ 没有 planner `order` 的 speaker **无法**派生合法 turnId；
- 因此**必须先冻结** turnId 的来源（例如引入独立的 runtime ordinal 维度），**在此之前不得实现**；
- **不得修改** `memberTurnIdFor` 的既有公式（M1 identity 契约冻结）。

## I. Cap contract（**未冻结，需先决策**）

产品语义（M3.4 UI 文案）：`maxResponders` = **每轮最多由多少个角色回复** ⇒ 默认倾向 **INTERJECT 不得增加实际 responder 数超过 cap**。
若产品希望"点名/插话可突破 cap"，那是**显式的 policy 语义变更**（需要新的 policy 字段与契约版本），
**不得**由 runtime 偷偷放宽。**该问题解决之前不得实现 INTERJECT**。

## J. Targeting / Recent contract（未冻结）

- **Targeting**：被点名者是否"自动获得插话权限"**未决定**；无论结论如何，`targetSpeakerIds` 是用户事实，**不得**被 runtime 修改或扩展；
- **Recent**：INTERJECT 成功发言后会产出 canonical assistant 消息，因此**按现有 recent 派生规则自然会进入下一回合的 recent**；
  这是否就是期望行为需显式确认（若不希望，需要额外规则）。二者本阶段均**不实现**。

## K. Cancel / Persistence / P23 contract（冻结）

- **Cancel**：任何 interject candidate 必须尊重唯一的 `_gTurn.cancelled`；**不得**出现第二 cancel authority；
- **Persistence**：INTERJECT 的 runtime state **必须 ephemeral**：无 DB、无 localStorage/sessionStorage、无 canonical metadata；
- **P23**：只有**真正 admitted 且执行 SPEAK** 的 MemberTurn 才进入 P23；INTERJECT 契约**不得**直接进入 delivery；
  五核心对 `interject` / `admission` 符号的引用必须保持 **0**。

## L. Future prerequisites（实现 INTERJECT 的前置清单）

1. **候选来源决策**（§C：A/B/C/D/E 选一或组合，且不得引入第二 authority）；
2. **groupOrder 规则**（§G）；
3. **turnId 来源**（§H；不得改 `memberTurnIdFor`）；
4. **cap 语义**（§I）；
5. targeting / recent 交互确认（§J）；
6. 实现阶段必须复用既有 hard gates、one-turn-per-speaker、ephemeral 与 P23 边界。

在上述 1–4 未冻结之前，INTERJECT 保持 **BLOCKED / 不可实现**。
